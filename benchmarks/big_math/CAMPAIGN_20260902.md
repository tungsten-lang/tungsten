# BigNum campaign ledger, 2026-09-02

Twenty items from a fresh read of `bin/tungsten bench bignum --all --quick`,
plus a devirtualization track for the native lane. Each item follows the
SUGGESTION_AUDIT keep gate: same-build same-host baseline, one variable per
change, affected cells re-measured with the same timing policy, GMP
differential/self-test checks, kept only on a win without a >5% regression,
raw JSON retained under `baselines/`.

Host: Apple M5 Max, macOS, AC power, load average ~10 (other sessions
compiling throughout). Cross-lane numbers carry that noise; the C-vs-GMP
paired quartets are ratio-robust, the native lane is min-of-N absolute.

Known measurement caveat (recorded before any change): the C lane times
CLOCK_MONOTONIC wall time, the native lane CLOCK_THREAD_CPUTIME_ID. On a
loaded host the native lane is undercharged for preemption, so W/native
below 1.0 on heavy ops is partly clock, not code.

### Item 1: `## i64` hints in big_int_bitwise.w — KEPT

`campaign-item01-bitwise-i64-hints-2c9269c1-m5max-20260902.json`. Twelve
untyped locals assigned from raw-i64 fns (`as`/`bs` signed sizes in the
and/or/xor entries, `top4` in the 4-limb AND arm, `n`/`top` in the
`&=`/`|=`/`^=` mutate kernels) were boxed by `__w_int_fast`; a top limb
with bit 63 set does not fit i48, so every 4-limb AND allocated a heap
BigInt through `bigint_from_i64` and never released it (sampled: 1553/1554
samples in `bigint_arena_take`). Native lane ns/op before -> after:
and@1 9.6 -> 8.5, and@2 8.1 -> 8.2, and@4 124.2 -> 5.6, and@8 9.6 -> 8.8;
or@4 9.3 -> 9.3, xor@4 9.5 -> 9.3 (controls). C lane unchanged (it does not
run the source kernel). Gates: native self-test passed at build,
`spec/numeric/bigint_bitwise_spec.w` and `spec/core/increment_assign_spec.w`
pass compiled. Root cause to carry to the compiler track: lowering should
infer a raw i64 slot for a local assigned from a fn whose declared return
type is raw i64 instead of boxing it.

### Item 2: arena remote-free epoch — KEPT

Premise verified before the change with a compiled probe (`acc = a & b`,
4-limb operands, no release): ns per iteration 54 / 69 / 173 / 587 at
25k / 50k / 100k / 200k iterations, i.e. O(iterations) per allocation.
Sampling put 2539 of 2558 samples inside `bigint_arena_take`: on every
freelist miss `bn_arena_drain_remote` walked every 2 MiB chunk header (one
cache miss each) to find nothing pending. Now remote pushers bump a
process-wide atomic epoch after publishing a slot and each arena walks
only when the epoch moved since its last drain (teardown forces a drain).
After: 75 / 50 / 69 / 66 / 48 / 50 ns at 25k .. 800k. Benchmark cells are
unaffected by construction (steady state never misses the hot slot).

### Items D, 14, 15: tagged Core receiver devirtualization — KEPT

`campaign-native-devirt-bitwise12-wallclock-…json` vs baseline (native lane
now wall-clock, so every native number is if anything pessimised).
`Tungsten.LOCK_THE_DOORS!` previously devirtualized only `self` and fresh
`X.new` receivers; a `(BigInt)`-typed parameter was rejected because BigInt
carries a runtime dispatch tag. The tag is what makes it devirtualizable: a
heap BigInt has no IC table, so the runtime always resolves it through the
type-class superclass walk (BigInt -> Int -> Integer -> Real), which
`locked_direct_method_fn` reproduces. `lower_method_call` now emits, for a
declared BigInt receiver under the lock, a tag-guarded direct call to that
Core worker with the ordinary IC send as the slow arm (a demoted inline int
or a program subclass takes the slow arm); `a <=> b` with both operands
guard-proven BigInt and Core's `Real#<=>` unmodified collapses to
`w_spaceship`. `locked_direct_method_fn` also fails closed when a class on
the walk registers the selector with a default-parameter range or splat
the runtime would probe first (`BigInt#to_s(base = 10)`), instead of
resolving past it to a superclass entry.

Native lane ns before -> after: cmp@1 7.2 -> 3.0, @4 7.7 -> 3.7, @16 8.3
-> 5.9, @64 19.0 -> 12.8; abs@1 3.8 -> 1.8, @4 4.8 -> 1.6, @16 4.6 -> 1.6,
@64 4.7 -> 1.5 (now equal to the C lane's O(1) tag flip); powmod@1 359.6
-> 216.6 (item 5 plus direct `Int#pow`), isqrt unchanged (already a ccall
seam). tostr still routes through `w_int_to_s` and fromstr through the
String IC row (String has a live IC table for `to_i`, so no direct call is
sound there). Gates: stage 1 == stage 2 identity after the compiler change;
`spec/compiler/bigint_core_receiver_locked_direct_spec.w` (new) covers
alias/negative/demoted receivers, a program reopen of an inherited selector
winning over Core, and default-arity `to_s`; all prior locked-direct specs
pass; `compiler/test/test_type_facts.sh` fixtures pass through the stage
compiler.

### Item 3: release of the dead previous value on loop-carried BigInt reassignment — KEPT

E4 stage 4 in the mutate-if-unique walker (`lowering/analysis.w`): `r =
<arithmetic>` whose leaves are ints or plain var reads, admitted over a
dominating literal seed (the same ownership proof the word-dest shape
uses), no longer kills r; and the LAST top-level statement handing r back
(implicit `r` / `return r`) is treated as the ownership transfer that ends
the scope instead of an alias. Lowering (`assign.w`) captures r's value
before the RHS runs and emits `w_bigint_release_dead_distinct(old, new)`
after it; the runtime entry is a no-op for inline ints and for an alias the
op handed back (pointer test on top of the shared mark every immutable
entry sets). Bare `r = y`, stores, calls, blocks, interpolation and any
earlier/nested return still kill (fail closed); main is excluded because
its bindings are also globals. Kill switch `TUNGSTEN_BIGINT_RELEASE_REASSIGN=0`.

Compiled probe (`acc = a & b` over 4-limb operands, tail `acc`), release on
vs off, TUNGSTEN_ALLOC_PROFILE arena takes and ns/iteration:
25k iterations 21 vs 25,020 takes, 10 vs 64 ns; 200k 21 vs 200,020, 7 vs
44 ns; 800k 21 vs 800,020, 7 vs 38 ns; 3.2M 21 vs 3,200,020, 7 vs 36 ns.
Memory is O(1) instead of O(iterations) and the loop runs 5-9x faster
(hot-slot handoff instead of a fresh arena slot per iteration). The first
probe version ended in `acc.bit_length`, a call that (correctly) kills the
candidate, and showed no effect; the walker is deliberately that
conservative. Gates: stage 1 == stage 2 identity with the pass compiled
into the compiler itself; `spec/compiler/bigint_release_reassign_spec.w`
(new: mixed arithmetic, negation alias, identity alias, self-read,
demote-and-regrow, bare copy / array store / closure / unseeded parameter
adversaries) and `spec/compiler/bigint_mutate_unique_spec.w` pass.
