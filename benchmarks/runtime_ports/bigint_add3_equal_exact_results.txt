BIGINT POSITIVE EQUAL-WIDTH ADD@3 — EXACT SOURCE CHECKPOINT
==========================================================

Scope
-----

This checkpoint ports only distinct positive three-limb plus three-limb
BigInt addition from `bigint_add_equal_fast`.  Native Tungsten preserves the
current C route exactly:

  * exact hot capacity-four result allocation;
  * the literal AArch64 `bn_add3_fixed` load/add-with-carry/store schedule;
  * an unconditional fourth-limb carry store; and
  * normalized positive size three or four.

Negative operands, mixed signs, every neighboring equal width, unequal
widths, and open-world BigInt#+ replacements retain their previous routes.
This is the exact-port checkpoint; no native-only arithmetic redesign is
included.

Native-versus-C boundary decision
---------------------------------

The separate direct-C harness still has an advantage: the final same-binary
screen measured 3.500 ns for Tungsten C and 3.888 ns for native Tungsten
(`W/native=0.9002`).  That lane bypasses the call a Tungsten source program
must make.  Replacing add@3's native leaf with an early `ccall` in the same
ordinary Tungsten program was decisively worse: 21 alternating 110 ms pairs
measured C-call/native at 1.377376 with 0/21 C-call wins.  The native leaf is
therefore retained, while every unported equal width deliberately keeps C.
