BIGINT POSITIVE FORTY-LIMB BY ONE-LIMB MULTIPLY — EXACT SOURCE CHECKPOINT
===========================================================================

Scope
-----

This checkpoint ports only the distinct raw-positive-header 40-by-1 and
1-by-40 boxed-BigInt arms. Native Tungsten preserves C's exact outer shape:

  - the same exact capacity-sixty-four hot allocation;
  - one call to the unchanged `bn_mul_1_f40` kernel;
  - the same carry store in limb forty; and
  - positive size forty when carry is zero, otherwise size forty-one.

The scalar kernel is deliberately unchanged. Shape selection, allocation,
and result publication move to native Tungsten. Receiver order is preserved,
and a genuine open-world BigInt `*` reopen remains observable. Signs,
squaring, and every neighboring width retain their former routes.

Focused validation
------------------

- a feature-off oracle build passes 100,000 exact native/C differentials,
  alternating both operand orders and checking exact result sizes;
- compiled and interpreted public checks pass independent closed-form
  products, every named representation/route case, and 1,000 randomized calls;
- both result widths, signs, squaring, and neighboring widths are covered;
- a real BigInt `*` reopen replaces ordinary and direct seams;
- production, feature-off, diagnostic, fixed-kernel-off, and N-by-1-off
  native harnesses pass the complete 25-operation self-test;
- compiler LLVM reaches a byte-identical self-hosted fixed point, assembles,
  and verifies under LLVM 22;
- `make -C runtime runtime.o` and `git diff --check` pass; and
- linked-body and hardware-counter route proofs pass.

This is an exact-fidelity checkpoint at parity, not a speed claim. The final
fixed 48/64 outer-leaf migrations remain separate measured work.
