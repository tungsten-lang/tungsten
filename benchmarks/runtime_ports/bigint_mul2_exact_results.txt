BIGINT POSITIVE TWO-BY-TWO-LIMB MULTIPLY — EXACT SOURCE CHECKPOINT
==================================================================

Scope
-----

This checkpoint ports only the distinct, raw-positive-header, positive
two-by-two-limb arm from `bigint_mul_any_routed` /
`bigint_mul_positive_equal`. Native Tungsten preserves C's exact contract:

  - the same capacity-four hot allocation;
  - the same four unsigned 64-by-64 products;
  - the same middle- and high-limb carry schedule;
  - four unconditional result stores; and
  - positive size three when the top limb is zero, otherwise size four.

The source leaf is the linked release/LTO AArch64 instruction schedule copied
from C's `bn_mul_eq2_inline`, not a new multiplication algorithm. The runtime
admits it only after the existing positive-pair block has already proved two
distinct heap BigInts with raw positive headers. Pointer identity remains the
separate `sqr@2` checkpoint. Sign overlays, negative headers, one-/three-/wider
widths, and internal C callers keep their former paths. A genuine open-world
BigInt `*` reopen remains observable.

Exact linked arithmetic
-----------------------

The linked strong `__w_bigint_mul2_src` contains the hot allocator, followed
by the same 21 arithmetic/load/store instructions as C after only base-register
renaming:

  ldp, ldp,
  umulh, mul, umulh, mul, mul, umulh, umulh, mul,
  adds, cset, adds, cset, adds, cinc, adds, stp, adcs, adc, stp

The source then performs C's exact three-instruction top-limb size choice and
publishes the header. No C multiplication kernel call remains in the source
leaf.
