BIGINT POSITIVE THREE-BY-THREE-LIMB MULTIPLY — EXACT SOURCE CHECKPOINT
====================================================================

Scope
-----

This checkpoint ports only the distinct, raw-positive-header, positive
three-by-three-limb arm from `bigint_mul_any_routed` /
`bigint_mul_positive_equal`. Native Tungsten preserves C's exact contract:

  - the same capacity-six request, rounded to the hot capacity-eight class;
  - the same nine unsigned 64-by-64 products;
  - the same column-by-column carry schedule;
  - six unconditional result stores; and
  - positive size five when the top limb is zero, otherwise size six.

The source leaf is the linked release/LTO AArch64 schedule copied from C's
`bn_mul_eq3_inline`, not a new multiplication algorithm. The runtime admits
it only after the existing positive-pair block has already proved two
distinct heap BigInts with raw positive headers. Pointer identity remains the
separate `sqr@3` checkpoint. Sign overlays, negative headers, one-/two-/four-
and wider widths, and internal C callers keep their former paths. A genuine
open-world BigInt `*` reopen remains observable.

Exact linked arithmetic
-----------------------

The linked strong `__w_bigint_mul3_src` contains the hot allocator, followed
by the same 60 arithmetic/load/store instructions as C after only pointer-base
and register renaming. An automated extraction confirms both schedules have
60 instructions and identical mnemonic sequences. The source then performs
C's exact top-limb size-five/size-six choice and publishes the header. No C
multiplication kernel call remains in the source leaf.
