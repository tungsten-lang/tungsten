BIGINT POSITIVE FOUR-BY-FOUR-LIMB MULTIPLY — EXACT SOURCE CHECKPOINT
==================================================================

Scope
-----

This checkpoint ports only the distinct, raw-positive-header, positive
four-by-four-limb arm from `bigint_mul_any_routed` /
`bigint_mul_positive_equal`. Native Tungsten preserves C's exact split:

  - the same capacity-eight hot allocation;
  - row zero calls the unchanged tuned `bn_mul_1(n=4)` C kernel;
  - the remaining three four-limb add-multiply rows use C's literal linked
    96-instruction arithmetic/load/store schedule;
  - eight unconditional result stores; and
  - positive size seven when the top limb is zero, otherwise size eight.

This is not a flattened or approximate schoolbook replacement. The outer
fixed leaf moves to native Tungsten while its deliberately retained row-zero
primitive remains the exact C kernel. The runtime admits it only after the
existing positive-pair block has already proved two distinct heap BigInts
with raw positive headers. Pointer identity remains the separate `sqr@4`
checkpoint. Sign overlays, negative headers, one-/two-/three-/five- and wider
widths, and internal C callers keep their former paths. A genuine open-world
BigInt `*` reopen remains observable.

Exact linked arithmetic
-----------------------

The linked strong `__w_bigint_mul4_src` performs the capacity-eight hot
allocation, loads the first operand word, and calls the same `_bn_mul_1` with
literal `n=4`. The following native block has the same 96 instructions as
C's linked remainder after only base-register/offset normalization. An
automated extraction confirms identical 96-instruction mnemonic sequences.
The source then performs C's exact top-limb size-seven/size-eight choice and
publishes the header.
