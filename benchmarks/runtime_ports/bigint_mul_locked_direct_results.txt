BIGINT MULTIPLY — CLOSED-WORLD EXACT DISPATCH FOLLOW-UP
======================================================

Scope
-----

This is a native-only integration change after the exact positive mul1@1..8
ports were independently checkpointed through 2fb03dd0. It does not change
any of those arithmetic leaves.

When a program declares both `Tungsten.PROTECT_THE_CORE!` and
`Tungsten.LOCK_THE_DOORS!`, an exact `(BigInt BigInt)` multiplication site may
bypass polymorphic `w_mul` after exact heap-tag checks:

  - positive distinct 1x1 calls the committed mul1@1 leaf directly;
  - positive distinct 2..8-by-1 calls the committed Core source worker;
  - every other exact heap-BigInt pair enters `w_bigint_mul_builtin_exact`,
    which preserves the tuned C square, scalar, schoolbook, and wide routes;
  - a tag miss still calls the unchanged polymorphic `w_mul` entry;
  - syntactic `a * a` skips the new guard entirely.

The exact built-in boundary is also the Core worker's fallback after
language-level dispatch, avoiding a redundant return through `w_mul` without
changing open-world replacement semantics. The causal switch
`TUNGSTEN_BIGINT_MUL_LOCKED_DIRECT=0` restores the prior lowering.

  signs, inline demotion, syntactic square, and dynamic identity square;

error on the clean 2fb03dd0 baseline (`core/numeric/big_int.w:4773`, typed
BigInt#& header). It is not introduced by this optimization; the relevant
self-hosted two-generation fixed point is byte-identical as recorded above.
