BIGINT SQR@2 — CLOSED-WORLD NATIVE DISPATCH FOLLOW-UP
======================================================

Scope
-----

This is a native-only optimization after the exact two-limb square checkpoint
0d6eaefa. It does not change square arithmetic, allocation, representation,
normalization, or any C algorithm boundary.

At a syntactic `a * a` site in a program that declares both
`Tungsten.PROTECT_THE_CORE!` and `Tungsten.LOCK_THE_DOORS!`, receiver identity
and method-table immutability are compile-time facts. The generated caller now:

  - proves the exact BigInt tag once;
  - loads the raw signed-size header once;
  - enters the committed exact native sqr@1 leaf for size +1;
  - enters the committed exact native sqr@2 leaf for size +2;
  - enters the unchanged `w_bigint_mul_builtin_exact` boundary for every other
    BigInt shape; and
  - falls back to polymorphic `w_mul` on a stale/non-BigInt type fact.

The size checks use the raw header deliberately. A tag-overlay-negative value
still has a positive raw header and may square through the positive leaf; a
genuinely negative header stays on the exact C boundary. Open-world BigInt `*`
replacement semantics are unchanged. An independent compile-time switch,
`TUNGSTEN_BIGINT_SQR2_LOCKED_DIRECT=0`, restores the exact-checkpoint route and
is the causal benchmark control.

Counter and route proof
-----------------------

`tungsten flame --counters` on the candidate attributes the hot work to the
inlined source measure/warm path; `w_bigint_mul_builtin_exact` is absent, IPC is
9.16, and memory misses are effectively zero. With the feature disabled,
`w_bigint_mul_builtin_exact` accounts for 73.4% of sampled cycles and the TLS
address helper for another 22.8%, at similar IPC and with the same negligible
miss rate. The gain is therefore removal of boundary/TLS/dispatch overhead,
not an arithmetic or memory-system change.

Validation gates
----------------

  - candidate and feature-off locked-direct specs pass;
  - the focused spec covers positive and overlay-negative two-limb identities,
    the existing one-limb route, wider/dynamic identities, signs, stale type
    facts, and a non-BigInt receiver;
  - retained LLVM contains exactly one sqr@2 source-seam call in the candidate
    and none with the feature disabled; both modules assemble and verify;
  - final AArch64 contains the exact native sqr@2 instruction schedule inline
    at the protected+locked call site, with no hot call to the standalone seam;
  - candidate and feature-off native-lane self-tests pass;
  - two self-host compiler generations emit byte-identical LLVM; and
  - `git diff --check` passes.
