BIGINT POSITIVE FOUR-LIMB SQUARE — EXACT SOURCE CHECKPOINT
==========================================================

Scope
-----

This checkpoint ports only the pointer-identical, raw-positive-header,
four-limb arm from `bigint_mul_any_routed` / `bigint_mul_positive_equal`.
The native Tungsten worker is a literal copy of the current linked AArch64
leaf:

  - exact hot capacity-8 allocation;
  - the same four diagonal and six doubled cross products;
  - the linked C `mul` / `umulh` / `extr` / flag-chain schedule;
  - eight unconditional limb stores; and
  - positive size 7 when limb 7 is zero, otherwise positive size 8.

The stable seam is dedicated to `sqr@4`. A tag-overlay negative with raw
header +4 is admitted just as in C, while a real negative header and every
neighboring width retain their prior routes. A plain open-world BigInt `*`
replacement still wins over the narrow seam.

The benchmark compiler disables the already-committed closed-world square
shortcut (`TUNGSTEN_BIGINT_MUL_LOCKED_DIRECT=0` and
`TUNGSTEN_BIGINT_SQR2_LOCKED_DIRECT=0`) so ordinary source `a * a` reaches
this exact checkpoint. The runtime toggle `TUNGSTEN_BIGINT_SRC_OPS=0` then
pins the same binary to C for the causal control. Extending the closed-world
1..3 switch to sqr@4 is deliberately deferred to a separate native-only
tranche.

The literal exact source port is 14.76% faster than the C-pinned route. This
is still an arithmetic-ownership checkpoint: the gain comes from preserving
the fixed C schedule while removing its source-to-C routing overhead, not from
changing the multiplication algorithm.

------------------

    size-8 results, overlay-negative and negative-header inputs, receiver

  - a compiled feature-off differential compares the direct strong native
    worker against the pinned C boundary for 100,000 values, including both
    result widths and alternating signs;
  - 100,000 raw and 100,000 boxed runtime squares/multiplies through five

  - the plain BigInt `*` reopen spec passes;
  - feature-off and feature-on native-lane self-tests pass;
  - emitted compiler, spec, and native-lane LLVM modules assemble and verify
