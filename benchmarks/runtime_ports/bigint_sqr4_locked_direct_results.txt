BIGINT SQR@4 — CLOSED-WORLD NATIVE DISPATCH FOLLOW-UP
======================================================

Scope
-----

This is a native-only optimization after the exact four-limb square checkpoint
ef001b38. It does not change square arithmetic, allocation, representation,
normalization, or any C algorithm boundary.

At a syntactic `a * a` site in a program that declares both
`Tungsten.PROTECT_THE_CORE!` and `Tungsten.LOCK_THE_DOORS!`, receiver identity
and method-table immutability are compile-time facts. The generated caller:

  - proves the exact BigInt tag once;
  - loads the raw signed-size header once;
  - preserves the already-measured dense sqr@1..3 dispatch byte-for-byte;
  - routes the default arm through one outlined size-4 dispatcher, which enters
    the committed exact native sqr@4 leaf or tail-calls the unchanged
    `w_bigint_mul_builtin_exact` boundary; and
  - falls back to polymorphic `w_mul` on a stale/non-BigInt type fact.

The outlined default dispatcher is deliberate. Putting size 4 into the dense
switch, or testing size 4 directly in its caller, made LLVM rebalance the
existing 1..3 comparison chain and regressed the small controls. The retained
shape leaves that chain unchanged and isolates the larger exact sqr@4 worker
behind the default arm. The size key remains the raw header: tag-overlay
negative values square through the positive leaves, while true negative
headers retain the exact C path. `TUNGSTEN_BIGINT_SQR4_LOCKED_DIRECT=0`
restores the exact-checkpoint route and is the causal benchmark control.

Validation gates
----------------

  - candidate and feature-off locked-direct specs pass;
  - the focused spec covers positive and overlay-negative four-limb identities
    plus the existing one-, two-, and three-limb leaves, wider/dynamic
    identities, signs, stale type facts, and a non-BigInt receiver;
  - candidate and feature-off native-lane self-tests pass;
  - emitted compiler, spec, and native-lane LLVM modules assemble and verify
    under LLVM 22;
  - retained IR contains one noinline default dispatcher in the candidate and
    none with the feature disabled, while the exact sqr@4 worker remains the
    committed strong source seam;
  - linked AArch64 preserves the measured sqr@1..3 comparison chain and calls
    the outlined dispatcher only from its default arm;
  - two self-host compiler generations emit byte-identical LLVM; and
  - `git diff --check` passes.

Rejected layouts
----------------

Adding case 4 to the dense switch won strongly at sqr@4 but regressed sqr@1 by
9.3% and sqr@2 by 3.8%. Testing size 4 in the caller's default block had the
same comparison-tree problem. Outlining only the sqr@4 source seam still left
the destabilizing caller test. Those variants were rejected; only the compact
default-path dispatcher passed the target and control gates.
