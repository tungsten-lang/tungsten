BIGINT POSITIVE FIVE-LIMB SQUARE — EXACT SOURCE CHECKPOINT
==========================================================

Scope
-----

This checkpoint ports only the pointer-identical, raw-positive-header,
five-limb arm from `bigint_mul_any_routed` / `bigint_mul_positive_equal`.
The native Tungsten worker is a literal copy of the linked AArch64 `bn_sqr5`
leaf:

  - exact hot capacity-16 allocation for the ten-limb result;
  - the same five diagonal and ten doubled cross products;
  - the same fixed, intentionally noinline `mul` / `umulh` / `extr` /
    flag-chain schedule;
  - ten unconditional limb stores; and
  - positive size 9 when limb 9 is zero, otherwise positive size 10.

The dedicated stable seam admits the same tag-overlay negative with raw header
+5 as C. A real negative header, distinct equal boxes, and every neighboring
width retain their existing C routes. A plain open-world BigInt `*` reopen
remains observable. The compiler now accepts `; tungsten:noinline` in an
embedded-LLVM body so this exact port can retain C's deliberate leaf boundary.

The benchmark compiler disables the already-committed closed-world square
shortcut (`TUNGSTEN_BIGINT_MUL_LOCKED_DIRECT=0` and the sqr@2..4 direct
toggles) so ordinary source `a * a` reaches this checkpoint. The runtime
toggle `TUNGSTEN_BIGINT_SRC_OPS=0` pins the same binary to C. Extending the
closed-world switch to sqr@5 is deliberately deferred to the separate
native-only tranche.

------------------

    size-10 results, overlay-negative and negative-header inputs, receiver
    preservation, and a distinct-equal-value control;
  - a compiled feature-off differential compares the direct strong native
    worker with the pinned C boundary for 100,000 values, including both
    result widths and alternating signs;
  - the plain BigInt `*` reopen spec passes;
  - feature-off and feature-on native-lane self-tests pass;
  - the focused runtime object builds cleanly;
  - compiler, focused-spec, and native-lane LLVM modules assemble and verify
    under LLVM 22;
  - linked AArch64 arithmetic/store bodies normalize to the same 134
    instructions and SHA-256
    `c436f79f5dabd813aeb461d711fa0bda7f400722e59b09e8d2051a3392de201f`;
  - the native body retains C's explicit noinline boundary and adds only the
    exact three-instruction +9/+10 size return;
  - two self-host compiler generations emit byte-identical LLVM; and
  - `git diff --check` passes.
