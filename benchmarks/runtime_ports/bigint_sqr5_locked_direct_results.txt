BIGINT SQR@5 — CLOSED-WORLD NATIVE DISPATCH FOLLOW-UP
======================================================

Scope
-----

This is the separately measured native optimization after exact five-limb
square checkpoint 84b75272. The fifteen products, doubled cross terms, carry
order, ten stores, allocation class, and +9/+10 result publication remain the
literal committed C port.

At a syntactic `a * a` site in a program declaring both
`Tungsten.PROTECT_THE_CORE!` and `Tungsten.LOCK_THE_DOORS!`, receiver identity
and method-table immutability are compile-time facts. The retained shape:

  - leaves the caller's measured dense sqr@1..3 switch unchanged;
  - tests only size 5 in a new outlined default dispatcher;
  - executes that test before any frame, so every non-5 width tail-branches to
    the byte-identical committed sqr@4 dispatcher;
  - inlines the exact 134-instruction sqr@5 leaf into the size-5 arm; and
  - inlines the existing capacity-16 allocator wrapper, eliminating two
    native wrapper calls while retaining the TLS hot-slot lookup and fallback.

The first combined sqr@4/5 dispatcher was rejected: LLVM hoisted its 48-byte
frame onto every default width and produced >1% control costs. Splitting it
into a one-test sqr@5 dispatcher followed by a tail-chain restored the old
paths. Counter profiling then showed the remaining candidate as arithmetic
and allocation-bound rather than memory-bound; measured removal of the two
wrapper calls supplied the final win without modifying arithmetic.

`TUNGSTEN_BIGINT_SQR5_LOCKED_DIRECT=0` restores the exact-checkpoint locked
route and is the causal benchmark control. The capacity-16 allocator is also
used by the existing exact `mul1@8` source leaf, so that family is included in
the control matrix rather than treated as structurally unaffected.
