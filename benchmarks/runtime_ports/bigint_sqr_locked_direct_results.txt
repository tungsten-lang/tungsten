BIGINT SQUARE — CLOSED-WORLD NATIVE DISPATCH FOLLOW-UP
======================================================

Scope
-----

This is a native-only optimization after the exact `sqr@1` checkpoint
1ee4107b. It does not change square arithmetic, allocation, representation,
normalization, or any C algorithm boundary.

When a program declares both `Tungsten.PROTECT_THE_CORE!` and
`Tungsten.LOCK_THE_DOORS!`, an exact `(BigInt BigInt)` multiplication site
may bypass polymorphic `w_mul` after exact heap-tag and header-shape checks.
Pointer identity is now admitted:

  - a raw-positive-header one-limb identity calls the committed native
    64-by-64 product and exact C finisher directly;
  - every wider identity enters `w_bigint_mul_builtin_exact`, preserving C's
    fixed-square, Karatsuba, Toom, NTT, redirect, allocation, and
    normalization choices;
  - a tag miss still calls unchanged polymorphic `w_mul`;
  - distinct positive one-limb pairs and the existing 2..8-by-1 source
    workers retain their prior routes.

An overlay-negative identity is safe in the one-limb leaf because its raw
header is positive and a square is positive. A genuinely negative header is
not size +1 and therefore remains on the exact C dispatcher. Open-world code
cannot take this path because both executable contracts are required.

Route and validation gates
--------------------------

- candidate and feature-off focused locked-multiply specs pass;
- focused cases include positive and overlay-negative one-limb identities,
  wider syntactic/dynamic identities, signs, demoted type facts, and a stale
  non-BigInt receiver;
- all eight mul1 reopen specs plus the sqr@1 reopen spec pass with a compiler
  built from the changed source;
- retained LLVM shows the one-limb identity calling
  `__w_bigint_mul1_1_src`, wider identity calling
  `w_bigint_mul_builtin_exact`, and tag misses calling `w_mul`;
- final AArch64 inlines the one-limb identity as `mul` plus `umulh` and exact
  result publication; no extra arithmetic kernel was introduced;
- the counter profile attributes the hot native route to inlined
  `measure`/`warmed_sample`; `w_mul` is absent from the sampled hot list;
- native-lane self-tests pass for candidate and feature-off binaries;
- two self-host compiler generations emit byte-identical LLVM;
- emitted focused LLVM assembles and verifies under LLVM 22;
- `git diff --check` passes.
