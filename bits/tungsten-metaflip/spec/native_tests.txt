# Metaflip unit tests the root gate cannot run through the interpreter.
# Columns: path reason [shard]. Reasons:
#   native  - cannot run interpreted: needs a runtime call the interpreter
#             lacks, or exceeds its memory limit (the comment says which)
#   timeout - compute-heavy: exceeded the 120 s interpreted sweep budget
#   argv    - needs positional arguments (a parity driver, not a self-test)
#   gpu     - needs a Metal device
#   manual  - runs compiled without arguments but is kept out of the shards;
#             the comment says why (it fails today, or it asserts wall-clock
#             behaviour that a loaded machine breaks)
# A native or timeout row names its shard: spec/metaflip_native_shard<N>_spec.w
# compiles and runs the tests of shard N, one `tungsten spec/<name>_test.w`
# child at a time from the bit root, so the root gate reaches them as it
# reaches the interpreted shards. argv, gpu and manual rows have no shard and
# no automatic runner: run them through their driver scripts or by hand.
# spec/metaflip_test_manifest_spec.w fails when a native or timeout row lacks
# a shard, when a shard has no wrapper, and when a wrapper has no tests.
#
# The trailing `Ns compiled` is the CPU time (user + system) of one cold
# `tungsten spec/<name>_test.w` on 2026-11-12 (Apple M5, compile included;
# the compile is 9 to 14 s of it). Wall time on an idle machine is about the
# same; on that day's machine, at a load of 50 to 60 on 18 cores, it was 3 to
# 10 times as long (nine cold tests in a row took 290 to 310 s). The shards
# are balanced on those seconds at about 80 each, so that a cold shard stays
# under the gate's 300 s watchdog at such a load too, with room for the
# runtime archive that the first compile of a cold bit cache builds (about
# 30 CPU-s). Rebalance, or add a wrapper, when a shard drifts above about 100.
