## 2026-07-29 continuation — exact xorshift circuit preimages

All eleven official `xorshift_r*` SAT rows are complete, topologically ordered
32-bit circuits rather than generic XOR-heavy formulas. Variables 1--32 are
the sole inputs; every later variable is defined exactly once by a rendered
XOR, AND, or OR gate; a sequence of xorshift32 state transitions is folded
into an accumulator by word XOR or 32-bit ripple addition; and 32 trailing
units pin the accumulator word.

The retained specialist recognizes that exact wire graph, including the
generator's final unused xorshift step and gapped sum outputs when the last
fold is an addition. It then partitions the finite 2^32 input domain
across at most ten workers. The search is deliberately model-only: domain
exhaustion says nothing, while a hit is replayed through every recognized gate
and the resulting full assignment must satisfy the original DIMACS before SAT
is published. A one-wire near-shape is a regression fixture and must be
rejected by the recognizer.

## Banked negative: loosening the BVE bounds (2026-07-28)

Hooks `WASSAT_BVE_MARGIN` / `WASSAT_BVE_OCC_CAP` / `WASSAT_BVE_OUTCAP`
(commit `2d7fc15`, inert when unset). Elimination counts are deterministic, so
this is safe to bank even though the run was contaminated:

| row | margin 0 (default) | margin 16 | margin 64 + 1M cap |
|---|---:|---:|---:|
| `minand064` | **11,820 eliminated** | 0 | 7,106 |
| `smulo016` | 0 | 0 | 0 |
| `qg3-09` | 0 | 0 | 0 |

Loosening the growth margin unlocks elimination nowhere and destroys it on the
one row where BVE currently works. Mechanism: a pivot whose resolvents
overflow the packed output buffer is rejected outright, so the buffer converts
a more permissive margin into *fewer* eliminations — raising it 60x in step
does not rescue the result, so the buffer is a confound rather than the cause.
**Do not re-run margin sweeps.** The qg/bitvector families need a different
elimination rule, not a looser one.

## Read the `c stats` line with care

Two wrong diagnoses in this document came from it, so it is worth stating
plainly: `c stats` reports the **winning arm's** artifact, and
`preprocess_ms` is **time-to-answer, not stage time**. A raw-arm or SLS-arm
win therefore prints `probes=0 vars_substituted=0 vars_eliminated=0` no matter
what the preprocessing arms did. To find out whether a stage ran and what it
cost, use `WASSAT_PROFILE=1` and read the `pre.*` lines.

## Mid-search inprocessing: BUILT, measured, and it loses (2026-07-28)

The doc called this the #1 structural gap, so it was implemented rather than
argued about. `WASSAT_INPROCESS=<conflicts>` re-runs equivalent-literal
substitution from the `reduce_db` site in `solve_loop` -- already a level-zero
point, already rebuilding watches and binary lists, and `substitute_equivalences`
is already designed for repeated calls (`congruence_rounds` loops it, `@subst`
is allocated once and its chains resolved in `unsubstitute`). Default 0.

| row | off | every 5k | every 20k | rival |
|---|---:|---:|---:|---:|
| `shuffling-1` | 8.5s | 9.8s | 8.5s | 1.37 |
| `minand064` | 3.4s | 3.4s | 3.4s | 0.38 |
| `blocks-4-ipc5` | 21.0s | 24.5s | 21.9s | 5.01 |
| `bench_1614` | 22.4s | **59.9s** | 24.2s | 10.90 |
| `gensys-icl003`, `SAT_dat.k10` | DNF | DNF | DNF | 2.67 / 9.69 |

**And the mechanism, which is the useful part.** It is not that the pass fails
to fire — it fires and finds real equivalences. Cumulative substituted
variables on `shuffling-1`: 1312 at load, then 1332, 1381, 1415, 1420, 1425,
1430, 1433. Each mid-search pass finds 3-49 new equivalences, ~9% more over the
whole search, and pays a full arena rewrite plus watch/binary rebuild for it.

So the gap is NOT "we do not inprocess". It is that SCC substitution is the
wrong pass to repeat: it consumes BINARY clauses, and CDCL learns mostly long
ones, so the implication graph barely grows (edges stay ~45,200 across every
pass). CaDiCaL's mid-search value comes from subsumption, strengthening and
BVE over the LEARNED set, which is a different and much larger build.
**Do not re-try periodic substitution.** The knob stays, inert, so the next
attempt starts from a measured baseline.

## SLS plateau retirement: the original (min-based) measurement

The SLS arm holds a core for its whole flip budget, and on an UNSAT instance
local search can never answer. Removing it outright is worth 24% on
`shuffling-1` and 10% on `smulo016` — but COSTS 15-21% on `qg3-09`/`qg5-13`,
so the static choice is wrong in both directions. The principled version is to
let the arm retire itself when its best-unsat count stops improving
(`WASSAT_SLS_PLATEAU`, window in flips; `WASSAT_SLS_PLATEAU_N`, windows
without progress).

On a hand-picked set it looked excellent — `shuffling-1` 10.84 -> 8.30s,
`smulo016` 6.11 -> 4.82, `qg3-09` 0.87 -> 0.67, `qg5-13` 0.93 -> 0.76, with
every row the walker wins bit-identical.

**On the full breadth set it is a null: geomean 1.0037 over 36 rows, and total
wall gets worse (76.9s -> 86.0s).** One row explains it: `em_7_3_6_fbc` at
**4.82x**. It is SATISFIABLE and its walker needs a long flat stretch before
breaking through, so a plateau test cannot distinguish "stuck forever" from
"about to succeed" — and retiring early discards the arm that would have won.

The asymmetry is the point: a false retirement costs the whole instance, a
correct one saves one core. Any window conservative enough to be safe is too
conservative to pay. Shipped OFF.

**This is the third time this session a hand-picked set has inverted on
breadth** (after arm-count width 2, and vivification). The set was mostly
UNSAT rows for a change whose whole risk lives on SAT rows. Choose the
validation set from where the change can HURT, not from where it should help.

## Hyper-binary resolution: mechanism confirmed, rows LOST (default off)

`probe()` throws away every non-failing trail, though each implied literal `m`
gives a valid RUP-checkable binary `(-lit | m)`. CaDiCaL substitutes 13.9% /
8.1% of variables on the quasigroup rows where wassat substitutes **zero** —
substitution runs, but Tarjan finds no SCC because the implication graph never
gains a derived edge. `WASSAT_HBR=<cap>` adds those binaries, filtered to the
non-redundant ones (reason clause length > 2; a literal derived through a
binary already has that edge).

**The mechanism works**: qg3-09 substitution goes 0 -> 54 variables (7.4% of
729, against CaDiCaL's 8.09%), and qg5-13 improves 1.10s -> 0.87s, a real
1.26x against its measured 1.14x floor. Sound: 200-case differential in both
modes, 101 checked proofs.

**But rows won drop 36 -> 34** (unsolved 7 -> 9): `2bitadd_10` WIN ->
UNSOLVED, `ibm-2004-03-k70` WIN -> TIE, `ais8` TIE -> LOSS, `crusti`
LOSS -> UNSOLVED. Both geomeans *improved* (survey 2.53 -> 2.60, competition
1.73 -> 1.87) — the opposite divergence from the subsumption axis, and another
reminder that the two objectives disagree. Default 0.

Worth retrying as a RACE AXIS rather than a global setting, which is what
rescued subsumption; there is no free cfg slot at width 4, so it would need
the width question reopened.

## Superseded detail: the min-based measurement, kept for the record — geomean 0.89

The pass CaDiCaL's mid-search advantage actually consists of, and the thing
the failed periodic-substitution attempt pointed at. `wassat_learned_subsume`
runs from `reduce_db` (already level zero, already rebuilding watches and

can be lost. Subsumption on the first pass, self-subsuming resolution on the
second. It fires hard — hundreds of clauses per pass on uuf250-01.

## What a conversion actually costs (2026-07-28)

`outcome()` scores against `TIE_BAND = 1.10`, not against parity: WIN needs
`ours * 1.10 < best_rival`, LOSS is `best_rival * 1.10 < ours`, everything
between is a TIE. Two consequences that should shape every future experiment,
because both cut against the instinct to optimise the geomean:

**1. A slowdown on a row already scored LOSS is free.** `qg5-13` is at 0.54x
and `bmc-ibm-12` at 0.32x. Making either 1.5x slower changes no row's status
and costs nothing against the rows-won objective. Trail reuse was read
pessimistically partly because its two clearest regressions land on exactly
these two rows.

**2. The cheapest conversions are small.** Ranked by the speedup needed to
cross into WIN, from the axis suite:

| row | status | vs best | speedup to WIN |
|---|---|---:|---:|
| `2bitadd_10` | TIE | 1.00x | **1.10x** |
| `em_7_3_6_fbc` | TIE | 1.07x | **1.03x** — but a 7.48x noise floor, not bankable |
| `bench_1614.smt2` | LOSS | 0.85x | 1.29x — 2.40x floor |
| `ais8.mis-97` | LOSS | 0.79x | 1.39x |
| `4pipe` | LOSS | 0.73x | 1.51x |
| `qg5-13` | LOSS | 0.54x | 2.03x |
| `qg3-09` | LOSS | 0.44x | 2.50x |

Below `qg3-09` the remaining seven losses need 3x to 10x and are not
conversion targets; they are where a technique has to change, not a constant
factor. Note how many of the cheap rows have noise floors larger than the gain
required — `2bitadd_10` and `4pipe` are the two worth chasing directly.
