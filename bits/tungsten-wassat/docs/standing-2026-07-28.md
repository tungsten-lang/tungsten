## Banked negative: loosening the BVE bounds (2026-07-28)

Hooks `WASSAT_BVE_MARGIN` / `WASSAT_BVE_OCC_CAP` / `WASSAT_BVE_OUTCAP`
(commit `2d7fc15`, inert when unset). Elimination counts are deterministic, so
this is safe to bank even though the run was contaminated:

| row | margin 0 (default) | margin 16 | margin 64 + 1M cap |
|---|---:|---:|---:|
| `minand064` | **11,820 eliminated** | 0 | 7,106 |
| `smulo016` | 0 | 0 | 0 |
| `qg3-09` | 0 | 0 | 0 |

Loosening the growth margin unlocks elimination nowhere and destroys it on the
one row where BVE currently works. Mechanism: a pivot whose resolvents
overflow the packed output buffer is rejected outright, so the buffer converts
a more permissive margin into *fewer* eliminations — raising it 60x in step
does not rescue the result, so the buffer is a confound rather than the cause.
**Do not re-run margin sweeps.** The qg/bitvector families need a different
elimination rule, not a looser one.

## Read the `c stats` line with care

Two wrong diagnoses in this document came from it, so it is worth stating
plainly: `c stats` reports the **winning arm's** artifact, and
`preprocess_ms` is **time-to-answer, not stage time**. A raw-arm or SLS-arm
win therefore prints `probes=0 vars_substituted=0 vars_eliminated=0` no matter
what the preprocessing arms did. To find out whether a stage ran and what it
cost, use `WASSAT_PROFILE=1` and read the `pre.*` lines.

## SUPERSEDED: parse-time boxed materialization — done, 7 rows

The five near-tie rows all lose by **less than their own parse time**:

| row | total | `cli.parse` | of which boxed | rival | gap |
|---|---:|---:|---:|---:|---:|
| `Large_b23` | 0.936 | 499ms | **302ms** | 0.79 | 146ms |
| `sembuster_7500` | 0.615 | 314ms | ~190ms | 0.48 | 135ms |
| `sembuster_4200` | 0.421 | 203ms | **124ms** | 0.32 | 101ms |
| `scc_9630` | 0.582 | 291ms | ~175ms | 0.55 | 32ms |
| `ak128` | 0.285 | 50ms | **29ms** | 0.25 | 35ms |

`wassat_parse_cnf_native` runs the fast C parser into flat `i64[]` mirrors and
then **eagerly builds a boxed `Array` per clause** — 10M allocations on
`Large_b23`. That loop is ~60% of parse time and on every row above it exceeds
the entire gap to the rival. Deleting it from the critical path wins
Large_b23, both sembusters and scc_9630, and ties ak128.

**Done (`this commit`):** the main path's `WassatConfig.new(nvars, clauses)`
is now `from_lens` — provably identical counters (`adopt_counts` consumes the
same histogram) without a 10M-clause walk. Worth 53ms on Large_b23, 26ms on
sembuster_4200.

**Remaining, scoped:** make the boxed list lazy (`wassat_formula_clauses`,
materialize-and-cache) and convert the consumers that run *before* an answer:

- `WassatPreprocess.new` — its internal `WassatConfig.new(@nvars,
  @input_clauses)` is a second full walk; needs the flat counters.
- the **SLS arm** (`portfolio.w:467`) — its constructor already rebuilds its
  own flat arrays from the boxed list, so reading flat directly *removes*
  work rather than adding it.
- the **XOR arm** (`portfolio.w:510`) — reads clauses only to group them by
  variable set; trivially flat.

`wassat_model_satisfies?` already takes the flat path, so a win does not force
materialization afterwards. The two thread landmines from `a2306c5` apply: both
arms run in worker threads, so they must read `i64[]` (never subscript a boxed
Array off-thread), and any new constructor arity must be explicit at every
call site.

## Two more banked negatives (2026-07-28, late)

**BVE occurrence-product cap is non-binding.** The earlier margin sweep was
confounded — every loosened-cap run also raised the margin, which independently
zeroes elimination. Tested at the DEFAULT margin, caps 4096 / 16384 / 65536 /
1,000,000 give *byte-identical* elimination counts on every row
(`minand064` 11,821, `smulo016` 1,820, `shuffling-1` 7,544, `qg3-09` 0).
Neither BVE bound is the limiter; the resolvent-growth test itself is, and
CaDiCaL's extra 9 points on minand064 come from doing more than plain BVE.
**Do not sweep BVE bounds again.**

**Forced shrinking does not rescue the DNF rows, and is instance-split.**
Full solves with `WASSAT_SHRINK=1` on all arms: `crusti` 94.1s -> **56.1s**
(1.7x, and inside the 60s budget), `SCPC-500-19` still unsolved, `spg_200_301`
92.5s -> 139.4s (1.5x WORSE). Same shape as every other axis here — genuinely
instance-split, which is what the race already samples (arms 1 and 3 shrink).
The crusti win is real but is not reachable by a policy flag without paying for
it on spg.

## The two structural gaps the rows keep pointing at

1. **Inprocessing / search quality on structured UNSAT.** With the BVE-speed
   theory dead, nearly every remaining loss (bitvector, qg, gensys,
   shuffling, blocks, mp1-ps, fla) is the same shape: comparable or better
   conflict rate, 4-40x the conflicts. gensys/mp1/2bitadd/SAT_dat all reduce to "CaDiCaL keeps
   simplifying mid-search and we simplify once at load." `substitute_equivalences`
   and `congruence_rounds` both assume a virgin root trail, so a mid-search
   variant is real surgery, not a flag.
2. **Trail reuse.** SCPC/crusti/spg reduce to props-per-conflict 20x+. Chrono
   with the distance cap is in and helps 1.7x, not 20x. CaDiCaL keeps ~69
   props/conflict on shapes where we pay 1,600.
